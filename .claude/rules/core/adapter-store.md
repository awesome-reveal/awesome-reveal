# Adapter store

- `createReveal` and `createCascade` share one store. It owns the state: the observer, `when ?? inView` and the play. It changes only two attributes of the attached element: it sets `data-awesome-reveal-attached`, and it removes `data-awesome-reveal` at the reveal. At a hide, the adapter sets it again: React and Vue render it from `revealed`, and Astro and the directives set it in the listener. React and Vue diff against their previous render, not the DOM, so the removal by core does not confuse them.
- Remove `data-awesome-reveal` before `onReveal`. The attribute keeps the CSS hold running, and its removal cancels the hold. So with the attribute still present, `getAnimations()` in the callback includes the hold, and its `finished` promise rejects with `AbortError`.
- Start `play` in the same task that removes `data-awesome-reveal`. Between the two, the element shows at full opacity, because `fill: "backwards"` applies the first keyframe only after `play` creates the animation.
- Hide in this order: cancel the animation, then tell the listener. Reveal in this order, in the same task: tell the listener, remove `data-awesome-reveal`, `play`, then call `onReveal`.
- `setOptions` replaces the options and does not merge them. Only a change of `when` or `threshold` restarts the observer. `createReveal` copies the options, because a directive can pass the same mutated object again.
- `when == null` means that the viewport decides. Use `??` and `== null`, not default values, because defaults do not apply to `null`.
- A revealed state plays once. `revealed` starts `false`, also with `when: true`, so that the server renders the element hidden. The first `attach` reveals and plays the entrance. A new element keeps the state and does not play again. The same element attached again right after `attach(null)` plays again only when `null` cancelled a running entrance. A finished entrance does not replay, because React Suspense and Activity detach and attach the same element when they hide and show it.
- The behavior spec of the adapters is the contract suite in `packages/test-utils` (`contract.ts`, `contract-ssr.ts`). Change a behavior there first, so that all adapters follow. A framework adapter cannot add behavior that core does not have.
- A cascade store reads the children in `play`, at the reveal, and not at `attach`, so children that the framework renders after the attach also animate. Imperative `cascade()` reads them when it is called. The adapter cascade hides the children, not the container: `[data-awesome-reveal="cascade"] > *`. With a hidden container, its background and border appear with no animation. A child with `display: contents`, such as an Astro island or host, gets no visible entrance.
- Each adapter renders the hidden markup itself, with `hiddenAttributes` or `cascadeHiddenAttributes`, and ships its own `reveal.css`. The library writes no inline style, so a strict CSP needs no `'unsafe-inline'`. `data-awesome-reveal`, `data-awesome-reveal-attached` and the `awesome-reveal-hold` keyframes are reserved.
- `reveal.css` hides only on screen and with no reduced motion, so print and reduced motion keep the author opacity. A separate `(scripting: none)` query cancels the hold. Focus before the attach ends the hold with `animation-duration: 0s`. Do not use `animation: none` there: a blur then starts a new 5 s hold, also after the first hold ended. Do not put `scripting` in the hiding query: browsers without the feature, such as Safari 16, then never hide. Before the attach, a short CSS hold hides the element, so markup that no script attaches shows again. `attach` sets `data-awesome-reveal-attached` on the element, and a CSS rule holds it after that. The hold after the attach is a CSS marker on the element, not a WAAPI hold, because a WAAPI hold cannot cover cascade children that render after the attach.
- The hold owns the `animation` property of hidden markup with `!important`. CSS cannot add an animation to the author list, and only an animation can end a hide after a time. Without `!important`, the stylesheet order and the specificity decide if the author animation or the hold wins. So an author animation on the same element starts at the reveal, and does not run when no script reveals the element. The READMEs tell users to animate an inner element.
- An attach after the hold ends hides the element again until it reveals. Do not detect the expiry of the hold: it conflicts with `when: false`, and it needs a style flush. The READMEs document the flicker.
