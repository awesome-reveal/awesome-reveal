# Core

- The root entry has only `reveal`, `cascade` and their types. Adapter machinery (`createReveal`, `createCascade`, the hidden attributes, the adapter options with `when` and `onReveal`) stays in `src/adapter.ts`, behind `@awesome-reveal/core/adapter`. Do not re-export it from `src/index.ts`. The package `dist.test.ts` and `tree-shaking.test.ts` check this boundary.
- Do not add options, aliases or helpers to the imperative API. Core stays a thin and predictable wrapper over WAAPI, with no hidden behavior. The option set in `src/types.ts` is frozen. Each entrance plays once: there is no `once` option, because a reset on exit would make the observer see the start state, and the element would loop at the viewport edge. Advanced motion uses native `Keyframe[]`, which wins over `from` at runtime. Generated keyframes stay internal in `src/animation.ts`.
- Imperative core needs no CSS. `motion()` creates a paused animation with `fill: "backwards"` at `currentTime = 0`, so the first keyframe hides the element before it enters the viewport. `play()` runs the animation only while it is paused, so a page `finish()` or `cancel()` before the entry wins. Do not rewind it, and keep the reference, so that `dispose()` still cancels an animation that page code started. Do not inject a `<style>` and do not import CSS from a core module. SSR pre-hiding belongs to the adapters.
- The generated entrance uses `opacity` and the individual `translate`, `scale`, `rotate` and `filter` properties, with replace keyframes and explicit neutral end values. Do not add `composite: "add"` to a generated keyframe: Chromium does not composite an effect that has an additive keyframe, so the entrance runs on the main thread and stutters. The cost is that the element's own values of these properties do not apply during the entrance. Do not read them with `getComputedStyle`: `reveal.css` forces `opacity: 0`, and a read forces a style recalculation for each target. The individual properties keep the author `transform`, so do not animate `transform`: it would replace that value. Explicit end values also avoid implicit keyframes, which are not Baseline. Chromium never composites an effect with `blur`, because a blur can move pixels.
- A start state with opacity 0 holds neutral values at offset 0, and its move keyframe is at a very small offset after 0. IntersectionObserver measures the transformed box, so a waiting offset can put a small element fully outside an `overflow` ancestor, and the element never reveals. The move starts while the element is transparent, so it is not visible. Other start states keep the move at offset 0, because a move at the play would jump visibly. These start states and native keyframes can still stay hidden in a clipping ancestor. The README documents this limit. A full fix needs a box that the entrance cannot move, such as the parent or an added element, and core rejects both. The adapters do not have this limit: their CSS hides with opacity only, and the animation starts at the reveal.
- Every failure leaves content visible. A throw from `animate()` shows the element with no animation. A throw from the observer constructor or from `observe()` plays the entrance at once. `dispose()` cancels the animations, so the elements go to their resting style. Do not add runtime validation for values that the browser validates.
- Reduced motion is automatic and has no option. When `prefers-reduced-motion: reduce` matches, `reveal` and `cascade` create no animation, and a later change to `reduce` disposes them.
- Print has no stylesheet in core. `motions()` adds each group to one shared `beforeprint`/`afterprint` listener pair. The listener moves each paused animation to its end time on `beforeprint`, past its backwards fill, and back to 0 on `afterprint`. Only paused animations move, so a playing entrance is not rewound. Every animation also gets `fill: "none"` until `afterprint`, so a running animation in its delay prints at rest and keeps its time. Do not pause it: the animation would lose the print time, and `play()` would see a paused animation. The adapter store plays through `motions()` too. `reveal.css` does not match print, but without the print listener the backwards fill would still hide an element in its delay. A real print in Chromium, also `page.pdf()` of Playwright, fires both events; `emulateMedia({ media: "print" })` fires none.
- `cascade` observes each container and animates its direct element children with the WAAPI delay `delay + index * interval`. `delay` moves the whole sequence, and there is no delay for each child separately: `interval` does that. It reads the children once, when it starts. Do not clamp a negative `interval`: WAAPI accepts a negative delay, which starts later children further into their entrance. Do not add a child selector or a timeline abstraction.
- `observe` uses the thresholds `[0, threshold]`. At each entry, it reveals at once when the viewport (`rootBounds`) is too small to show `threshold` of the element. A cross-origin frame gets `rootBounds: null`, so the check uses the frame viewport (`innerWidth` and `innerHeight`), which is the largest area that the frame can show. The viewport is the largest root, so in a scroll container that is too small, the element reveals when it leaves the visible area. Do not clamp the threshold instead: a clamp fails after the element grows.
- `observe` also reveals on `focusin`, and at the start when the element already contains focus, so a keyboard user does not focus invisible content. An element that matches `:focus-within` at the reveal plays no entrance, because a delay or a transparent start would hide the focused control: `reveal` and `cascade` cancel the animations, and the adapter store does not play but still calls `onReveal`. This check is at the reveal, not in the focus listener, so it also covers `when` and an attach again. `motions()` also listens to `focusin`, so focus during a running entrance or its delay finishes it. It uses `finish()`, not `cancel()`, so the `finished` promises resolve. It finishes only running animations: a `focusin` with no real focus before the reveal must not finish a waiting animation, or `play()` skips it. The adapters keep a `when: false` element hidden on focus, because `when` has priority over the viewport.
- Do not throw when an API is missing. Without IntersectionObserver, reveal at once. Without `Element.animate`, reveal with no animation.
- Do not use `window` or `document` at module level. Server renderers import core. A selector resolves to no elements when `document` is undefined.
- The `.d.ts` files carry the JSDoc, and the JS output has none. Write the option docs and defaults in the type JSDoc.
- A consumer bundle of an adapter includes core. The tree-shaking tests measure the core code in that bundle, so new code in `animation.ts`, `observe.ts` or `adapter.ts` counts against the size limits of all adapters.
- `report()` in `src/report.ts` throws from a microtask, once for each message on a page. An error from `onReveal` and the errors that `motion()` and `observe()` catch go to it. Do not report once per call: adapters create the motion at reveal time, so a list of components would report once per item. Do not throw from `observe`, `play` or `createReveal`, because a render or an effect can call them. An uncaught error in a React effect unmounts the root. Tests that touch a report stub `queueMicrotask`.
